# Computer

The VPS at a glance, live: its own desktop, what its Claude sessions are showing right now, its files, its programs and what fills its disk, Claude Code's state and its jobs, how busy the VPS is, and how Nova is doing. It's for admins. Everything except the desktop's **Control** switch **only shows**: nothing types into a session, edits, deletes, uploads, downloads, stops a program or changes a setting.

## What's new

- **Desktop · Screen · Files · Programs · Disk**: chips along the top of the big card. Computer opens on **Desktop**, the VPS's own desktop in the page (View only, or **Control** with an orange warning that changes are real, and **Full screen**). **Files** lets you browse every folder from the top (/), with where you are, a filter, sorting by name, size or when it changed, and opens text files (the first 200 KB, in colour) and pictures. Private things (keys, passwords, .env files, ssh, credentials) show their name only, and whatever only root can see shows a lock. **Programs** lists everything running (CPU, memory, when it started, who runs it, its command), grouped as Nova Bot, Nova Agent, Claude, web and system, sorted by CPU or memory, live. **Disk** shows which folders fill the disk as bars; tap one to look inside.
- Computer joins Nova Agent's Tools: the VPS's screen (its Claude sessions, live and read-only), Claude Code, CPU, memory and disk with the last half hour as small graphs, every part running on the VPS, the status page, the latest updates, the Fixer and the last backup. Portal → Admin → Computer has a big **Open Computer** to it.

## What it shows

- **Desktop**: the VPS's own desktop (XFCE), in the page. It starts when you open this part (3 to 5 seconds: "Starting the VPS's desktop…") and sleeps 15 minutes after nobody's watching; it's only loaded while Desktop is open. **View only** is the default: you see it but can't touch it. **Control** lets you use it, with an orange line: "You're controlling the VPS: changes are real". **Full screen** fills the screen with it; on a phone, pinch to zoom.
- **Files**: browse the VPS from / (the breadcrumbs say where you are; tap one to go back up). Each thing shows its size, when it changed (UK time) and who owns it; filter by name and sort by name, size or changed. Tap a text file to read its first 200 KB (code, settings and logs in colour) or a picture to see it. 🔒 **Only root** can see some folders and files: they stay locked (Nova Agent's own user reads, with no extra powers). 🙈 **Private** things show their name only ("Hidden: private"). Binary files say so. Nothing can be changed, deleted, uploaded or downloaded.
- **Programs**: everything running on the VPS: its name, group (Nova Bot, Nova Agent, Claude, web, system), who runs it, CPU now, memory, when it started and its command (secrets hidden). Sort by CPU or memory, show one group, filter; it's live every 4 seconds while it's open. View only: nothing can be stopped from here.
- **Disk**: the biggest folders in /, /srv, /var or /home as bars; tap one to see inside it. Measuring takes a while, so it happens slowly in the background (it never slows the VPS or the page) and is kept for 10 minutes. Folders only root can read count as smaller than they are, and it says so.
- **The VPS's screen**: each Claude session on the VPS has a chip along the top. **Nova-VPS (Remote Control)** is the one you drive from the Claude app on your phone; each job handed to the VPS has its own while it works. The box shows the session's last 60 lines, in its own colours, and keeps to the bottom as new lines come (scroll up to read back; it stays where you are).
- **Jobs on the VPS**: every job handed to the VPS, newest first: **Working**, **Done** or **Stopped**, how long it took, and what it was asked. Tap one to read its last words in the box.
- **Claude Code**: its version, whether it's signed in, whether Nova-VPS is connected, how many jobs are working and how many finished today, and what it's working on (the newest part of `HANDOFF.md`). On your phone: Claude app → Code → Nova-VPS.
- **The VPS**: CPU, memory, disk and how long since it last restarted, with CPU and memory over the last 30 minutes, and every part running on it (Nova Bot, Nova Agent, the web server, the mail sender) with a green, amber or red dot.
- **Nova**: the status page's parts with their dots, the last 5 updates to Nova Agent and Nova Bot (times in the UK's time), the Fixer (how many fixes wait for you, its last check and looks check, and **Open the Fixer**) and when the last nightly backup was.
- It's live every 4 seconds while it's on screen, and pauses while it isn't (another panel showing, or the tab hidden).
- One screen: the page never scrolls; the screen, the jobs and each card scroll inside themselves. On a phone the whole board scrolls inside its own box; on a phone held sideways the screen and the cards sit side by side.

## Inside Nova Agent

Computer is in the Panels window and on the bar, under Tools. It's for admins: sign in to Portal as an admin. It reads the VPS, so it only shows anything on the VPS's Nova Agent (https://nova.novacane.co.uk/agent/computer); on the studio PC it says so. The page is called Computer; inside it, the machine is "the VPS".

## How it works

- Desktop: noVNC at `/vps-desktop/` (Nova Bot's `vps/desktop-setup.sh`; Caddy asks Nova Bot's `/app/api/admin-check` first, so only signed-in admins get it; the block is in `vps/Caddyfile` too, because every deploy writes that file afresh).
- Files, Programs and Disk: `src/computer-explore.ts` (`/computer-api/files`, `file`, `image`, `procs`, `disk`; admins only, the same gate). Paths must start at /, never contain `..`, and are followed to where they really lead; a private name (on the path asked for or where it leads) is never opened. Only ordinary files are read (never devices or pipes), at most 200 KB of text and 5 MB of a picture; at most 2,000 things a folder. Every line of text shown passes `redact()`. Programs come from `/proc` (CPU from two looks 4 seconds apart). Disk is `nice -n 19 ionice -c 3 du -x -b --max-depth=1`, one at a time, at most 3 minutes each.
- `src/computer.ts` gathers everything for `GET /computer-api/state` (admins only, like the Fixer: online, Nova Bot passes it on over the link for admins; both link lists allow just this one read-only address).
- The screen: `tmux list-windows` and `tmux capture-pane -p -e` for Nova Agent's own user (`nova-agent`). Nova Agent's service has a private `/tmp`, so tmux's folder is shared into it (`/etc/systemd/system/nova-agent.service.d/tmux.conf` and `/etc/tmpfiles.d/nova-agent-tmux.conf`, made by Nova Bot's `vps/agent-setup.sh`). Colours become HTML on the server (`ansiToHtml`: every character escaped, other escapes dropped).
- Jobs: `/srv/nova-agent/work/logs/<when>-<name>.log` and `.task` (from `work/bin/run-job.sh`); a job is done when its log ends with `=== DONE`.
- **No secrets leave**: every line from a session, a log, the handoff or an update passes `redact()`: the values of Nova Agent's own keys (read from its environment, never sent) and anything shaped like a key or token (`sk-…`, `Bearer …`, `NAME_KEY=…`, long random strings, JWTs) become •••.
- The VPS: `/proc/stat` and `/proc/meminfo` every 30 seconds (the last half hour kept in memory), `statfs` for the disk, `systemctl is-active` for the parts. Nova: the status page (`/status.json`), `git log` of the VPS's Nova Agent and Nova Bot, the Fixer's own state, and the last backup from the VPS's status service (`127.0.0.1:8788/status`, its token made from Nova Agent's key).

## Tests

`test/computer-explore.spec.ts`: what's private (and that it's never opened, even through a link), redaction of every text file, `..`, relative paths and NUL refused, locked folders, devices never read, the caps (folder size, text size, picture size), binary files and pictures, programs (CPU, memory, start, redacted commands, groups), disk (biggest first, measured once in the background, politely, then kept), and every view admins only. `scripts/check-fit.mjs` opens each part at every size with long samples.
`test/computer.spec.ts`: secrets never leave (key values, `sk-`, `Bearer`, `NAME_KEY=`, long random strings, while paths and short git hashes stay), colours become safe HTML (and markup never gets through), jobs (working or done, how long, their task and last words), the handoff's newest part, the whole state (with no secrets anywhere in it), the studio PC's message, and admins only (anyone else gets 403). Nova Bot's `test/agent-relay.spec.js`: the link passes on only `GET /computer-api/state`, for admins.
